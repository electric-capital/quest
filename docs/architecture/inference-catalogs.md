# Inference Provider Catalogs

## Overview

The model lists behind Settings > Inference Providers (see [Inference Providers](inference-providers.md)): where each provider kind's "Add model" typeahead looks (`GET /admin/inference-providers/instances/{id}/catalog`, or the shared OpenRouter route) and where the metadata snapshot of a newly added model -- name, context and output limits, pricing, thinking levels -- is copied from, so nothing at request time depends on a catalog. `fetch_instance_catalog()` in `chat/llm/model_setup.py` dispatches on the kind's `catalog` source (`INSTANCE_KINDS` in `config/inference_providers.py`) for every admin path, including the first-run quick setup, whose `suggested_models()` picks live next to it. Every module produces the OpenRouter row shape, so `search_catalog()` / `catalog_snapshot()` in `chat/llm/openrouter_catalog.py` apply unchanged; the cached catalogs serve a stale copy with the error alongside when a fetch fails, so the UI degrades to custom-id entry.

### OpenRouter catalog cache

`chat/llm/openrouter_catalog.py` fetches `https://openrouter.ai/api/v1/models` (public, no key) and caches the normalized list (`id`, `name`, `context_length`, `top_provider.max_completion_tokens`, per-token prices converted to $/1M, and the per-model `reasoning` object reduced to its `mandatory` / `default_enabled` / `supported_efforts` / `default_effort` keys by `normalize_reasoning()` -- null for a model without reasoning) in `DATA_DIR / "openrouter_catalog.json"` for 24 hours. `get_catalog()` serves the cache while fresh, re-fetches otherwise (or on `refresh`), and on a failed fetch returns the stale cache -- or an empty list when there never was one -- with the error alongside, so the UI degrades to custom-id entry. `search_catalog()` (substring on id/name, id-prefix hits first) backs the typeahead; `catalog_snapshot()` produces the per-model snapshot on add.

### Fireworks catalog cache

`chat/llm/fireworks_catalog.py` builds the catalog from two authenticated Fireworks endpoints (both need the instance's bearer key, unlike OpenRouter's public list), so `get_catalog(api_key, refresh=False)` takes the instance's stored key and, with no key, reports `"No API key saved yet."` instead of fetching:

- `GET https://api.fireworks.ai/inference/v1/models` (OpenAI-style `{"data": [...]}`) is the authoritative list of ids the key can call serverlessly: the shared `accounts/fireworks/models/<name>` models, the `accounts/fireworks/routers/<name>` speed/cost routers and the `auto` / `firerouter/auto` meta-routers, each with `supports_chat` / `supports_tools` / `supports_image_input`, `context_length` and a `kind`. Entries with `kind: EMBEDDING_MODEL` (embedding and reranker models, which Fireworks still marks `supports_chat`) or `supports_chat: false` are dropped; `kind: ROUTER` entries are kept and flagged `router` in the typeahead.
- `GET https://api.fireworks.ai/v1/accounts/fireworks/models` (the management API, `pageSize=200`, following `nextPageToken` up to `MAX_PAGES`) is consulted best effort for the shared models' `displayName` and `deprecationDate` (a past date drops the model); a failure there only costs the friendly names (routers get `<last segment> (router)`, other unnamed ids their last path segment). It exposes **no pricing** -- `serverlessModes` is empty on every public entry and the AIP-160 `filter` parameter rejects the documented field names (checked 2026-10-08) -- so Fireworks snapshots carry `pricing: null` and `max_completion_tokens: null` (no per-model output cap is published either); the cost reports price Fireworks rows from the static `_FIREWORKS_PRICING` table in `db/llm_pricing.py` instead.

### NEAR AI catalog cache

`chat/llm/nearai_catalog.py` fetches `https://cloud-api.near.ai/v1/models` -- **public**, no key, which is why `get_catalog(refresh=False)` takes none and the instance catalog route serves it before a key is saved -- and caches the normalized list in `DATA_DIR / "nearai_catalog.json"` for 24 hours with the same stale-on-failure degradation as the OpenRouter cache. The list uses the OpenRouter row shape (`id`, `name`, `context_length`, `top_provider.max_completion_tokens`, per-token price strings in `pricing.prompt` / `completion` / `input_cache_read`), so `normalize_openrouter_entry()` (the exported `openrouter_catalog._normalize_entry`) does the base normalization and NEAR AI snapshots carry real $/1M prices incl. the automatic prompt-cache read rate. On top of that each entry publishes `input_modalities` / `output_modalities` and `supported_features`, which the module uses to:

- keep only **chat models** (`is_chat_model()`): entries must take text in and produce text out (image generators such as FLUX, speech-to-text such as Whisper, embedding models and other non-text outputs are dropped; a sparse entry with no modality lists is kept so a new model is never hidden), and the text-in text-out embedding / reranker ids are dropped by name (`_NON_CHAT_ID_RE`);
- flag `capabilities` (`tools` when the feature list says so, `vision` for image input) and a `detail` of `vision` / `reasoning` for the typeahead. An entry whose `supported_features` is **empty** -- NEAR AI publishes empty lists on freshly added models -- gets `capabilities: null` (unknown) rather than `[]`, so the typeahead never claims "no tool support" for it.

A second public endpoint, `GET /v1/model/list` (paginated `{"models": [...], "total": n}`, followed with `limit` / `offset` by `fetch_tee_metadata()`), carries each model's TEE metadata under `metadata`: `providerType` (`vllm` = NEAR's own TEE fleet, `external` / `chutes` = relayed to a third-party provider), `verifiable` and `attestationSupported`. `classify_entry()` reduces them to one **`tee` label** per entry: `enclave` only when all three say so, `proxy` for everything else incl. a model the metadata list does not name (fail closed). The metadata list is best effort -- when it cannot be fetched every model is labelled `proxy` and the failure is logged, the model list itself stays required. The label is cached with the entry (a cache written before the label existed reads back as `proxy` until its TTL refresh), rides along in `catalog_snapshot()` into the instance model (`normalize_instance_model()` keeps it only when it is one of `TEE_LABELS`), surfaces as `ModelSpec.tee` and the admin model row's `tee`, and is rendered as the Enclave / Proxy badge. It is informational: nothing in the request path reads it and no attestation is verified -- the badge says where NEAR AI *claims* the model runs.

Checked 2026-10-12: 53 chat models, 5 of them `enclave` (Qwen and GLM open-weight models plus `openai/privacy-filter`); the frontier vendors' models are `proxy`.

Entries use the OpenRouter row shape plus `detail` / `capabilities` (like self-hosted discovery, so `search_catalog()` / `catalog_snapshot()` apply unchanged); `capabilities` holds `tools` / `vision`, merged from both lists, and the typeahead flags models without `tools`. The normalized list is cached in `DATA_DIR / "fireworks_catalog.json"` (`FIREWORKS_CATALOG_FILE`) for 24 hours -- the serverless list is the same for every key, so one cache serves every Fireworks instance -- with the same stale-on-failure degradation as the OpenRouter cache (HTTP errors carry the Fireworks `error.message`, e.g. `HTTP 401: The API key you provided is invalid.` for a revoked key).

### TrustedRouter catalog cache

`chat/llm/trustedrouter_catalog.py` mirrors the NEAR AI module for `https://api.trustedrouter.com/v1/models` -- **public**, no key, cached in `DATA_DIR / "trustedrouter_catalog.json"` for 24 hours with the same stale-on-failure degradation. The list is the OpenRouter row shape (modalities under `architecture.input_modalities` / `output_modalities`, capability flags in `supported_parameters`), so `normalize_openrouter_entry()` does the base normalization and snapshots carry real $/1M prices incl. `input_cache_read`. The module keeps only text-in text-out chat models (dropping image / video / speech / embedding outputs and embedding / reranker ids) and flags `tools` / `vision`; an entry with no `supported_parameters` gets `capabilities: null` (unknown).

Checked 2026-10-12: 659 entries (~4 MB), 572 of them chat models.

### Anthropic, OpenAI and Gemini catalog caches

The direct vendor kinds share the plumbing in `chat/llm/catalog_cache.py` (`get_json()` with the vendor's `error.message` on failure, `read_cache()` / `write_cache()`, `serve_catalog()` -- 24h TTL, stale-on-failure, an empty list with the error when there never was a cache) and each keep only their URL, headers, entry normalization and metadata enrichment; all three are read with the instance's own key (`get_catalog(api_key, refresh=False)`, "No API key saved yet." without one), cached in `data/anthropic_catalog.json` / `data/openai_catalog.json` / `data/gemini_catalog.json`, and expose `suggested_wire_ids(models)` for the quick setup. Rows have the OpenRouter shape plus `detail` / `capabilities` (like self-hosted discovery) and, when a Vertex registry entry serves the same model, `registry_id`.

- **Anthropic** (`chat/llm/anthropic_catalog.py`): `GET https://api.anthropic.com/v1/models` paginated with `after_id` (`x-api-key` + `anthropic-version` headers). The API publishes only `id` and `display_name`, so context / output caps, the `reasoning` object and the pricing snapshot come from the registry entry `registry_entry_for_wire_id()` (chat/llm/config.py) matches -- the registry key or the entry's `vertex_model_id` with any `@date` / `-YYYYMMDD` suffix dropped on both sides -- via `reasoning_from_registry_entry()` and `static_pricing_snapshot()` (db/llm_pricing.py); an unmatched model gets 200K / 8K, no price, no thinking sublevel. Suggestions: the undated aliases of non-deprecated registry models, one per entry.
- **OpenAI** (`chat/llm/openai_catalog.py`): `GET https://api.openai.com/v1/models` (bearer). The list carries no metadata and mixes every model type, so `is_chat_model()` keeps the `gpt-*` / `o<n>*` / `chatgpt-*` ids minus the audio, realtime, image, search, transcription, embedding, moderation and Responses-API-only variants, and `KNOWN_MODELS` (keyed by family, a dated id matching its undated family via `family_of()`) supplies name, limits, pricing and the `reasoning` object; unknown chat ids get a derived name, defaults and no price. Known families sort first in table order. Suggestions: the table's undated ids the key can call.
- **Gemini** (`chat/llm/gemini_catalog.py`): `GET https://generativelanguage.googleapis.com/v1beta/models` paginated with `pageToken` (`x-goog-api-key`). Entries publish `inputTokenLimit` / `outputTokenLimit` and `supportedGenerationMethods`; only `generateContent` models survive, and the non-chat families the method list does not rule out (embeddings, Imagen, Veo, TTS, Live audio, ...) are dropped by id fragment. Pricing and `reasoning` come from the matching registry entry as for Anthropic; the API's own limits win over the registry's. Suggestions: the non-deprecated registry models, one per entry.

### Self-hosted model discovery

`chat/llm/local_catalog.py` asks a `local` instance's server for its models -- live and uncached, since what a local box serves changes whenever a model is loaded or pulled -- and returns entries with the same keys as an OpenRouter catalog entry (plus `detail` and `capabilities` for the typeahead), so `search_catalog()` / `catalog_snapshot()` from the OpenRouter module apply unchanged:

- `openai`: `GET <base_url>/v1/models`. The `id` is what the request must name (llama.cpp: the model path or `--alias`; vLLM: the served model name; LM Studio: the model key). llama.cpp reports the loaded context size in `meta.n_ctx` (older builds only the training size `n_ctx_train`, with `GET /props` `default_generation_settings.n_ctx` as the fallback), so `context_length` is exact there and `None` (→ the conservative default) elsewhere; `detail` carries the parameter count / quantization / owner when reported.
- `ollama`: `GET /api/tags` for the pulled models (family, parameter size, quantization, and on recent versions the training context and capabilities), with `POST /api/show` (bounded to 40 lookups, 4 at a time) filling in `model_info."<arch>.context_length"` and `capabilities` for older servers. `context_length` is what the provider will request as `num_ctx`: the training size capped at `DEFAULT_OLLAMA_CONTEXT_LENGTH` (32K -- Ollama sizes the KV cache from it), editable per model afterwards. A model whose capabilities lack `tools` is flagged "no tool support" in the typeahead.

**Context window sizing.** This app's system prompt (tool definitions, system-skill index, workspace instructions) is roughly 17K tokens on a Qwen/Llama tokenizer before any conversation history, so a self-hosted server must allow a context of at least 32K: llama.cpp must be started with `-c 32768` (or more; a 16K server rejects the very first turn with `exceed_context_size_error`, which surfaces as the conversation's error bubble), and an Ollama model's `context_length` in the instance config -- the requested `num_ctx` -- must stay at the 32K default or higher. The Models panel of a self-hosted card says so.

Neither kind of server publishes a marketing name, so `name` is derived from the id by `friendly_name()` (`qwen2.5:0.5b` → `Qwen2.5 0.5b`, `/models/llama-3.2-3b-instruct-q4_k_m.gguf` → `Llama 3.2 3b Instruct Q4 K M`). A server that cannot be reached returns `{"models": [], "error": ...}`; `default_snapshot()` (zero pricing, the default Ollama context) covers custom ids and unreachable servers when a model is added anyway. The stored key, when present, is sent as a bearer token on every discovery request too.

| `chat/llm/nearai_catalog.py` | Cached public NEAR AI Cloud catalog (`get_catalog(refresh)`, `fetch_catalog()`; chat-model filter `is_chat_model()` over modalities + `_NON_CHAT_ID_RE`, capability flags with null-for-unknown in `_normalize_entry()`, the `/v1/model/list` TEE metadata via `fetch_tee_metadata()` folded into the fail-closed `tee` label by `classify_entry()`, `NearAICatalogError`; the quick setup's `suggested_wire_ids()` over the curated `SUGGESTED_WIRE_IDS`); also what the NEAR AI health check consults |

| `chat/llm/local_catalog.py` | Live self-hosted model discovery (`discover_models()` over `/v1/models` + `/props` or `/api/tags` + `/api/show`), `friendly_name()`, `default_snapshot()` |
| `chat/llm/openrouter_catalog.py` | Cached OpenRouter catalog fetch, `normalize_openrouter_entry()` (shared with the NEAR AI catalog), `search_catalog()`, `catalog_snapshot()` (passes a NEAR AI entry's `tee` label through) |
