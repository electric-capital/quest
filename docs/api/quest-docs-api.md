# Quest Docs API

## Overview

REST endpoints for Quest Docs (user- and project-owned markdown documents; see [Quest Docs Architecture](../architecture/quest-docs.md)). This is the UI surface. Models never call it: they use the seven doc tools and the `write_doc` action request described in the architecture doc. Four routers, all mounted in `quest.py`:

- `chat/docs/routes.py`: list, create, read, rename, mode, asset, download, delete (request models `CreateDocRequest`, `UpdateDocRequest`, `SetDocModeRequest`);
- `chat/docs/share_routes.py`: sharing (`AddDocShareRequest`);
- `chat/docs/edit_routes.py`: content save, image upload and delete (the handlers read and bound their own bodies);
- `chat/docs/history_routes.py`: revisions, restore, copy (`RestoreRevisionRequest`, `CopyRevisionRequest`).

Every handler goes through `chat/docs/service.py` (or `ui_writes.py` / `history.py`, which reuse its pipeline) and `db/doc_store.py`. The frontend types are in `frontend/src/api/types.ts` and the client in `frontend/src/api/docsApi.ts`. Not to be confused with the Google Docs integration ([Docs API](docs-api.md)).

## Authentication, Gate and Visibility

- **Auth**: `get_current_user_cookie_or_apikey_checked`, so either the session cookie or a Bearer `users.api_key` works, and the admission check (`require_user_allowed`) runs on every request (see [Chat API](chat-api.md)). The routes live under `/app/api`, so the model's `curl_proxy_*` tools (`/api/*` only) cannot reach them. The sandbox tool API port does not serve them either.
- **Gate**: every handler first returns 403 `docs_disabled` while the `docs` feature gate is closed for the user ([Feature Gates](../architecture/feature-gates.md)).
- **Visibility**: every by-id route resolves the doc through `_get_doc_for_ui()`, which calls `service.get_visible_doc()` with `run_kind="ui"`. A doc the user cannot see (not the owner, no share) is 404 `doc_not_found` with exactly the body a nonexistent id gets. So is a doc of a public project while the `public_projects` gate is closed for the viewer **or for the doc's owner** (`project_id` set and `mode == "public"`; a project doc mirrors its project's flag), so a project hidden from its owner is frozen for the share recipients too. That covers every by-id route of all four routers, matching the project routes' hidden-public-project rule, and access comes back when the gate reopens.
- **Ownership**: rename, the mode route, delete, share management and image delete require ownership, so a visible doc the user does not own is 403 `forbidden`.
- **Write access**: the content save, image upload and every history route require the UI write verdict `free` (owner or write share, the row's `access.can_edit`), else 403 `forbidden`. The history routes check this right after visibility, before anything else.

## Response Shapes

**Doc row** (built by `_ui_row()` / `_ui_rows()` in `chat/docs/routes.py`, one batched user lookup per response; shape documented in the module docstring and in the `Doc` type): the store's doc dict (`_doc_to_dict()` in `db/doc_store.py`: `id`, `owner_id`, `project_id`, `title`, `description`, `mode`, `content_size`, `asset_count`, `last_write_source`, `created_at`, `updated_at`) plus:

- `scope`: `user` or `project`;
- `shared`: the doc has any share row;
- `shared_with_me`: the caller is not the owner;
- `permission`: the caller's effective share (`read` / `write`, the higher of a direct and an everyone row); null for the owner;
- `owner`: `{id, name, email}` for non-owners; null for the owner;
- `shares`: the roster `[{id, user_id, permission, created_at, user}]`, where `user_id` null (and `user` null) is the everyone row, and `user` is `{id, name, email}` (a deleted account keeps its id with null name/email). Present **for the owner only**;
- `last_write_source`: raw for the owner (`conversation:<id>`, `ui:<user_id>`, legacy `ui`, `action_request:<id>`); blanked to null for non-owners, since the owner's conversation ids are not a share recipient's business. It names the writer of the current body: UI image uploads and deletes keep it unchanged;
- `last_write_user`: `{id, name, email}` for the owner when `last_write_source` is `ui:<user_id>` (null when that user is gone), or `action_request:<id>` whose approved card was proposed by someone other than the owner, a write-share recipient (`{id, name: null, email: null}` when that proposer is gone); null otherwise and always for non-owners. The viewer footer reads it ("you" / the name / "a deleted user", "<name> (approved change)" / "a deleted user (approved change)");
- `access`: what the UI may offer. `can_rename`, `can_delete`, `can_share` and `can_delete_assets` are true for the owner; `can_edit` is true for the owner or a write share (content save, image upload, History); `can_switch_mode` is always false (no doc's mode is switchable; the key stays for the frontend type); `write` is the `ui` verdict, `free` for the owner or a write share and `denied` otherwise.

Timestamps are naive-UTC ISO strings. `updated_at` is also the optimistic-concurrency token. Share changes do not bump it.

**Version** (History; built in `chat/docs/history.py`, whose module docstring defines it; `DocVersion` in `types.ts`): `id` (`<YYYYMMDDTHHMMSSZ>-<n>`, null for the current body), `written_at` (when that body was written, ISO `...Z`), `replaced_at` (from the id, null for the current body), `size`, `source` (raw, owner only), `source_kind` (`conversation` / `action_request` / `ui` / `unknown`), `source_label` (who wrote it, phrased for this viewer; rules in [Quest Docs Architecture -- History](../architecture/quest-docs.md#history)) and `conversation` (`{id, title, project_id}`, owner only).

**Errors** are `HTTPException(detail={"error": <code>, "message": ...})`, so the JSON body is `{"detail": {"error", "message"}}`. The one exception is the optimistic-concurrency conflict of rename, content save and restore, which is a **flat** 409 body `{"error": "stale_update", "message", "current": <doc row>}` (no `detail` wrapper, like `PUT /routines/{id}`; built by `_stale_conflict()`). Pydantic or query validation failures on the base router, such as `limit` outside 1..200 or a missing `title`, are FastAPI's standard 422. The sharing, editing and history routes type their bodies loosely or read them by hand, so their bad bodies are 400s.

## Endpoints

### Docs

- **GET `/app/api/docs`** (`list_user_docs`). Query: `project_id?`, `shared?` (bool, default false), `limit?` (1..200), `cursor?`. Three independent keyset streams, sorted by `updated_at` descending then `id` descending, every row passing the access rule:
  - default: the caller's **own** user docs (no project). User docs shared with the caller are not here;
  - `project_id`: that project's docs. The project must be the user's and visible through `_get_visible_project()` (so a public project hidden by the `public_projects` gate counts as missing), else 404 `project_not_found`;
  - `shared=true`: docs shared **with** the caller (a direct or an everyone share) that the caller does not own, user and project docs alike (`doc_store.list_docs_shared_with()`); docs of a public project are left out while the caller's or the doc owner's `public_projects` gate is closed. Combined with `project_id` it is 400 `invalid_request`.

  Without `limit` the whole stream is returned. With `limit`, keyset paging: `next_cursor` is `<updated_at>|<doc_id>` built from the last row, echoed back as `cursor`; a malformed cursor is 400 `invalid_cursor`. Each stream pages on its own. The response is always `{docs: [row...], has_more, next_cursor}`, with `next_cursor` null when there are no more rows.
- **POST `/app/api/docs`** (`create_ui_doc`, 201). Body: `title`, `description?`, `mode?`, `project_id?`. Creates an **empty** doc owned by the user with `last_write_source="ui:<user_id>"` (`service.create_doc_from_ui`). A user doc (no `project_id`) is always private: `mode` omitted or `"private"` creates it, and `mode: "public"` is 400 `user_doc_mode_private` ("User docs are always private. Create the doc inside a public project to make it public."), whatever the `public_projects` gate says; it is checked after title / description / `invalid_mode` validation. The only way to create a public doc is a `project_id` of a public project. A project doc always takes its project's mode, and a supplied `mode` that disagrees is 400 `project_doc_mode_inherited`; the frontend never sends `mode`. Errors: 404 `project_not_found` (checked first, then again in the service); 400 `invalid_title` / `invalid_description` / `invalid_mode` / `user_doc_mode_private` / `project_doc_mode_inherited` / `invalid_request`; 409 `duplicate_title` (titles are unique case-insensitively per owner, project **and mode**); 500 `doc_storage_error`. Returns the row. Publishes `doc_list_changed` + `doc_changed`.
- **GET `/app/api/docs/{doc_id}`** (`get_ui_doc`). Returns the row plus `content` (the whole `doc.md`), `assets` and `last_write_conversation`.
  - `assets` lists the doc's images for the viewer's Assets panel: `[{name, size, mime}]`, regular files directly in `assets/` sorted by name, hidden names / symlinks / directories skipped, names outside `[A-Za-z0-9._-]+` skipped (`_LISTED_ASSET_NAME_RE`, fullmatch; all `add_asset` ever produces), MIME from `_INLINE_IMAGE_MIMES` by lowercased extension, built via `files.list_assets` in a thread. For a **read-only viewer** (verdict not `free`: a read or everyone-read share) it holds only the images `content` references (`ui_writes.referenced_asset_names()`, escaped spellings included, one pass per body in a thread, which also primes the asset route's cache); owners and write shares get all of them. The row's `asset_count` stays the total, unfiltered. The list endpoint does not carry it; 400 `invalid_doc_files` when `assets/` is a symlink or not a directory.
  - `last_write_conversation` is `{id, title, project_id}` of the conversation named by `last_write_source` (`_last_write_conversation()`: one `get_conversation_meta` lookup plus `ChatStorage._resolve_list_title`), or null when the source is not a conversation, the conversation no longer exists, or the caller is not the owner (blanked together with `last_write_source`). The viewer's "Last written by" footer reads it instead of fetching the conversation.

  Errors: 404 `doc_not_found`; 400 `invalid_doc_files` (missing body, or a symlinked / special `doc.md`); 500 `doc_storage_error`.
- **PUT `/app/api/docs/{doc_id}`** (`update_ui_doc`, owner only). Body: `title?`, `description?`, `expected_updated_at?`. Renames and/or changes the description. When `expected_updated_at` is given it must equal the row's current `updated_at` string exactly, else the flat 409 `stale_update`; omitting it skips the check. `updated_at` is bumped, and `doc_list_changed` + `doc_changed` published to the doc's audience, only when a field actually changes. A no-op save keeps the token. Errors: 403 `forbidden`; 400 `invalid_title` / `invalid_description` / `invalid_request`; 409 `duplicate_title`; 404 `doc_not_found`. Returns the row, without `content`.
- **PUT `/app/api/docs/{doc_id}/mode`** (`set_ui_doc_mode`). Not switchable: the route stays registered so an old client gets a clear error, but it refuses every doc, whatever the body (`SetDocModeRequest`, `mode?`) says. Checks run in this order: 403 `docs_disabled`; 404 `doc_not_found` (missing, hidden, or in a public project hidden by the `public_projects` gate); 403 `forbidden` for a non-owner; then the error from `service.mode_switch_refusal()`: 400 `user_doc_mode_private` for a user doc (always private), or 400 `project_doc_mode_inherited` for a project doc ("Project docs take their project's mode; it cannot be switched."). Nothing changes and no event is published. See [Quest Docs Architecture -- Mode is fixed at creation](../architecture/quest-docs.md#mode-is-fixed-at-creation).
- **GET `/app/api/docs/{doc_id}/assets/{name}`** (`get_ui_doc_asset`). Serves one embedded image from bytes read by `files.read_asset()`, which validates the name and opens the leaf `O_NOFOLLOW` + `S_ISREG` (unlike `FileResponse`, which would follow a symlink at open time). Headers: the real MIME type from `_INLINE_IMAGE_MIMES` in `chat/file_routes.py` (png/jpeg/gif/webp), `Content-Disposition: inline; filename="<name>"`, `Cache-Control: private`, `X-Content-Type-Options: nosniff`. 404 `asset_not_found` for anything that is not a regular, non-symlink file directly inside the doc's `assets/` with a raster extension (traversal and dot names included), and, for a read-only viewer, for an image the current body does not reference (same body). That check reads the body's referenced-name set from a 64-entry LRU keyed `(doc_id, updated_at)` (`_referenced_names()`), so a page of images costs one body pass.
- **GET `/app/api/docs/{doc_id}/download`** (`download_ui_doc`). Query: `format` = `md` (default) or `zip`; anything else is 400 `invalid_format`. `md` returns `doc.md` as `text/markdown; charset=utf-8`. `zip` returns `doc.md` + `assets/<name>` (`files.build_zip()`, run in a thread, temp file deleted after the response), and refuses with 400 `invalid_doc_files` when `assets/` holds a symlink or special file. A read-only viewer's zip holds only the images the archived `doc.md` references (`build_zip`'s `asset_filter`, evaluated under the doc lock against the body it archives). Both are `attachment`s named `<title>.<ext>` (`_download_filename()`: control characters and path/Windows-reserved punctuation stripped, 120 chars max, `doc` fallback), with an ASCII fallback plus an RFC 5987 `filename*`.
- **DELETE `/app/api/docs/{doc_id}`** (`delete_ui_doc`, owner only, delegating to `service.delete_doc_from_ui`). Under the per-doc write lock, captures the doc's audience, deletes the row (shares go with it), then the directory, best-effort and logged. Returns `{"deleted": true}`. Errors: 404 `doc_not_found`; 403 `forbidden`. The service publishes `doc_changed {doc_id, updated_at: null}` then `doc_list_changed` to the captured audience.

### Sharing

Both routes are owner only, run under the per-doc write lock (shielded) and return 200 with the **owner's row**. Share changes do not bump `updated_at`. Check order is in the `chat/docs/share_routes.py` module docstring: 403 `docs_disabled`, 404 `doc_not_found`, 403 `forbidden` (any non-owner, read or write share), then the body.

- **POST `/app/api/docs/{doc_id}/shares`** (`add_doc_share`). Body: `user_email?`, `everyone?`, `permission` (`ShareDocRequest` in `types.ts`). Exactly one target, a non-empty `user_email` XOR `everyone: true`, else 400 `invalid_request` (also for a non-string email or non-boolean `everyone`). `permission` must be `read` or `write`, else 400 `invalid_permission`. The email names a Quest user via `user_store.find_user_by_email_ci()`: an exact match wins, then an ASCII case-insensitive one; several case-variant accounts with no exact match are 409 `ambiguous_user`; no match (or the recipient deleted mid-request) is 404 `user_not_found` ("No Quest user has that email."); the owner's own email is 400 `cannot_share_with_owner`. Upsert through `doc_store.add_share`: one row per recipient and at most one everyone row, so sharing again changes the permission. Publishes `doc_changed {doc_id, updated_at: null}` then `doc_list_changed` to the owner and the recipient (every connected user for the everyone row), unless the permission was unchanged.
- **DELETE `/app/api/docs/{doc_id}/shares/{share_id}`** (`remove_doc_share`). 404 `share_not_found` for a malformed id or a share of another doc. The recipient loses access at once; a `write_doc` card they proposed is refused at Approve. Publishes `doc_changed {doc_id, updated_at: null}` then `doc_list_changed` to the owner and the removed recipient (every connected user for the everyone row).

### Editing

Check order on all three: 403 `docs_disabled`, 404 `doc_not_found`, 403 `forbidden`, then the body. Request bodies are read only after those checks, up to a cap: a declared `Content-Length` over the cap is refused before reading, and the streamed bytes are counted. A doc deleted, hidden by a revoked share, or frozen by a `public_projects` gate that closed (viewer's or owner's; `ui_writes.public_doc_frozen_for()`) while the request waited for the write lock is 404 `doc_not_found`; an unexpected filesystem error is 500 `doc_storage_error`. The writes are in `chat/docs/ui_writes.py` and record `ui:<user_id>` as the writer.

- **PUT `/app/api/docs/{doc_id}/content`** (`replace_doc_content`, owner or write share). JSON body `{content, expected_updated_at}`, both required (`UpdateDocContentRequest`). 400 `invalid_request` for another media type, invalid JSON, a non-object, a missing or non-string field, or text that is not UTF-8 encodable (e.g. a lone surrogate). CRLF is normalized to LF; 400 `content_too_large` over `DOC_MAX_CONTENT_SIZE` after that, or for a request body over `DOC_MAX_CONTENT_SIZE` x 6 + 64 KiB. The flat 409 `stale_update` (with `current`) when `expected_updated_at` is not the row's token, re-checked under the per-doc write lock. 400 `invalid_doc_files` when `doc.md` is missing, a symlink or a special file (as restore). A body identical to the stored one writes nothing (no revision, no bump, no event). Otherwise the replaced body is snapshotted into `revisions/` and `doc_changed` + `doc_list_changed` go to the doc's audience. No approval card, also for a write-share recipient of a private doc. Returns 200: the row plus `content` (the body as stored) and `changed` (`DocContentResponse`).
- **POST `/app/api/docs/{doc_id}/assets`** (`upload_doc_asset`, 201, owner or write share). `multipart/form-data` with `file` (required) and `alt` (optional; default the uploaded file's stem). 400 `invalid_request` for another media type, a malformed form or a missing `file` part; 400 `image_too_large` over `DOC_MAX_IMAGE_SIZE` (a declared or streamed body over `DOC_MAX_IMAGE_SIZE` + 64 KiB is refused before the parser finishes; at most one file part, 8 KiB per text field, at most `DOC_MAX_IMAGE_SIZE` + 1 file bytes read); 400 `invalid_image` unless the magic bytes say png / jpg / gif / webp (SVG and renamed text refused); 400 `asset_limit` past `DOC_MAX_ASSETS` / `DOC_MAX_ASSETS_TOTAL_BYTES`. The stored name is the sanitized file name plus the sniffed extension, `-2`, `-3` on collision. The body is not changed and no revision is taken; `asset_count` and `updated_at` are bumped (`last_write_source` keeps naming the body's writer) and the realtime events sent. Returns `{asset: {name, size, mime}, markdown: "![alt](assets/<name>)", asset_count, updated_at, previous_updated_at}` (`DocAssetUploadResponse`). The editor adopts `updated_at` as its token only when `previous_updated_at` equals the token it holds.
- **DELETE `/app/api/docs/{doc_id}/assets/{name}`** (`delete_doc_asset`, owner only). `name` is matched as a path, so `a/b.png` or an encoded `..%2Fdoc.md` reaches the handler and gets the same 404 `asset_not_found` as any bad, hidden, missing, symlinked or non-regular name; nothing outside `assets/` is touched and a symlink is never followed (`files.delete_asset()`). 409 `asset_in_use` while the current body references `assets/<name>` (also percent-, entity- or backslash-escaped; `ui_writes.asset_referenced()`, run in a thread); older revisions may still reference it. 400 `invalid_doc_files` when `doc.md` cannot be read (missing, a symlink or a special file). No revision is taken; `asset_count` and `updated_at` are bumped (`last_write_source` keeps naming the body's writer) and the realtime events sent. Returns `{deleted: true, asset_count, updated_at, previous_updated_at}` (`DocAssetDeleteResponse`).

### History

Editors only (owner or write share). Check order on all four: 403 `docs_disabled`, 404 `doc_not_found`, 403 `forbidden` ("History is available to people who can edit this doc.") for a read-only viewer, then the rest. Every function re-checks access against a fresh row after its file reads, so a share revoked, or a `public_projects` gate closed (viewer's or owner's), mid-request is 404 `doc_not_found` and a share downgraded to read is 403. A revision id that is malformed (it must fullmatch `[0-9]{8}T[0-9]{6}Z-[0-9]+`), missing, pruned, symlinked or not a regular file is the one 404 `revision_not_found`. A missing or non-regular `doc.md` is 400 `invalid_doc_files`; another filesystem error is 500 `doc_storage_error`.

- **GET `/app/api/docs/{doc_id}/revisions`** (`list_doc_revisions`). Returns `{current: Version, revisions: [Version...]}` (`DocRevisionsResponse`), revisions newest first, unpaged (at most `DOC_REVISION_MAX_COUNT`). The current version's record comes from `doc.meta.json`, falling back to `doc.md`'s mtime, an unknown source and the real size.
- **GET `/app/api/docs/{doc_id}/revisions/{rev_id}`** (`get_doc_revision`). Query: `diff?`. Returns the Version plus `content` (`DocRevisionDetail`). `diff=current` adds `diff` = `build_bounded_content_diff(old=<revision>, new=<current body>)` (the bounded `{added, removed, lines, truncated, total_old_lines, total_new_lines}` the `write_doc` card uses); any other `diff` value is 400 `invalid_request`.
- **POST `/app/api/docs/{doc_id}/revisions/{rev_id}/restore`** (`restore_doc_revision`). Body `{expected_updated_at}` (required, else 400 `invalid_request`). Writes the revision's body back through `ui_writes.replace_body_from_ui()`: access and the token re-checked under the per-doc write lock (flat 409 `stale_update` with `current`), the current body snapshotted first, the restored one recorded as `ui:<user_id>`. A body identical to the current one writes nothing. Returns 200 like the content save: the row plus `content` and `changed`.
- **POST `/app/api/docs/{doc_id}/revisions/{rev_id}/copy`** (`copy_doc_revision`, 201). Body `{title?}`. Creates a NEW **private user doc owned by the caller** from the revision (also from a project or public-project doc), with the description copied, the body written as `ui:<user_id>` and no revisions, and every asset the copied body references (escaped spellings included, as in the in-use rule) that the source still holds as a regular raster file within the caps copied under the same name. Title: the given one (400 `invalid_title`; 409 `duplicate_title` when the caller already has a user doc with that title) or `<title> (copy)`, `(copy 2)`, ... 400 `content_too_large` when the revision is over the body cap. Shielded: a cancelled request still completes the copy or cleans up. Returns the new doc's row and publishes `doc_list_changed` to the caller only.

### Not implemented

Deliberately not built: a working mode switch (spec 4.2's user-doc switch and 8.4's dialog). `PUT /app/api/docs/{id}/mode` exists only to refuse, since user docs are always private and a project doc keeps its project's mode. The UI never edits a description, although `PUT /app/api/docs/{id}` accepts one.

## SPA Routes

`GET /docs` and `GET /docs/{rest:path}` (outside `/app/api`) are not API routes: `serve_spa_docs` in `quest.py` returns the frontend's `index.html` so the Quest Docs deep links (`/docs`, `/docs?project=<id>`, `/docs/<id>`) survive a reload; the views are described in [Quest Docs Architecture -- Frontend](../architecture/quest-docs.md#frontend). To free the path, FastAPI's interactive docs moved off their defaults: Swagger UI is at `/api-docs` (OAuth2 redirect `/api-docs/oauth2-redirect`) and ReDoc at `/api-redoc`, while `/openapi.json` is unchanged (`tests/test_spa_docs_routes.py`).

## Error Codes

| Code | Status | Raised by |
|------|--------|-----------|
| `docs_disabled` | 403 | every route, gate closed for the user |
| `doc_not_found` | 404 | per-doc routes; missing docs, hidden docs and docs of a gated-off public project (viewer's or owner's gate) get identical bodies |
| `forbidden` | 403 | rename / mode route / delete / share management / image delete on a visible doc the user does not own; content save / image upload / every history route for a read-only viewer |
| `project_not_found` | 404 | list or create with a `project_id` that is not the user's visible project |
| `invalid_cursor` | 400 | list with a malformed `cursor` |
| `invalid_title` / `invalid_description` | 400 | create, rename (`service.validate_doc_metadata()`); `invalid_title` also on copy |
| `invalid_mode` | 400 | create with a `mode` other than `private` / `public` |
| `invalid_request` | 400 | create, rename (other store validation failures); list with `shared=true` and `project_id`; share without exactly one target; malformed content-save or upload bodies; restore without a token; a `diff` other than `current` |
| `user_doc_mode_private` | 400 | create with `mode: "public"` and no `project_id`; every mode-route call on a user doc |
| `project_doc_mode_inherited` | 400 | create with a mode that disagrees with the project; every mode-route call on a project doc |
| `duplicate_title` | 409 | create, rename, copy with an explicit title |
| `stale_update` | 409 (flat body with `current`) | rename, content save or restore with a stale `expected_updated_at` |
| `invalid_permission` | 400 | share with a permission other than `read` / `write` |
| `user_not_found` | 404 | share with an email no Quest user has |
| `ambiguous_user` | 409 | share with an email that matches several accounts case-insensitively and none exactly |
| `cannot_share_with_owner` | 400 | share with the owner's own email |
| `share_not_found` | 404 | share delete with a malformed id or a share of another doc |
| `content_too_large` | 400 | content save over the body cap; restore or copy of an over-cap revision |
| `invalid_image` | 400 | image upload that is not a png / jpg / gif / webp by magic bytes |
| `image_too_large` | 400 | image upload over `DOC_MAX_IMAGE_SIZE` |
| `asset_limit` | 400 | image upload past the per-doc image count or total size |
| `asset_not_found` | 404 | asset route (incl. an unreferenced image for a read-only viewer); image delete |
| `asset_in_use` | 409 | image delete while the current body references it |
| `revision_not_found` | 404 | revision read / restore / copy with a malformed, missing or pruned id |
| `invalid_format` | 400 | download with a format other than `md` / `zip` |
| `invalid_doc_files` | 400 | read / download / content save / image delete / history when the doc directory holds a missing body, symlink or special file |
| `doc_storage_error` | 500 | unexpected filesystem error (message names no path) |

## Realtime Events

Two per-user globals on the persistent WebSocket, sent to the doc's **audience**: the owner plus every direct share recipient, plus every connected user when the doc has an everyone share (see [Realtime](../architecture/realtime.md) and `chat/docs/events.py`):

- `doc_list_changed` (no payload): list views re-fetch their window;
- `doc_changed {doc_id, updated_at}`: an open viewer re-fetches, and can skip the fetch when it already shows that `updated_at`. `updated_at: null` means "this doc's existence or the receiver's access to it changed; re-fetch" (`events.publish_doc_gone_or_access_changed_to()`): sent on doc delete, share add / change / remove and project delete (per doc), always before that change's `doc_list_changed`, because none of those bumps `updated_at`.

`chat/docs/service.py` publishes for every model, action-request or UI body/asset write (UI writes and restore go through its `_finish_write()`) and for UI create and delete (delete: the null `doc_changed`, then `doc_list_changed`). The rename route publishes for itself, only when something changed. Share changes publish the null `doc_changed` then `doc_list_changed` to the owner and the affected recipient (every connected user for the everyone row; `publish_share_changed(doc_id, owner_id, recipient_user_id)`). A History copy publishes `doc_list_changed` to the caller only. The mode route never publishes, since it changes nothing. The project-delete route publishes, after its directory sweep, the null `doc_changed` per deleted doc to that doc's audience, then one `doc_list_changed` to the owner plus every recipient of the deleted docs.

Frontend consumers: `useDocs` (`frontend/src/hooks/useDocs.ts`, the sidebar Docs blocks and All Docs, including the "Shared with you" stream; 300 ms debounce) and `useProjectDocsIndex` (the All Docs per-project fan-out; 600 ms) refresh on `doc_list_changed`. `useDoc` (the viewer) re-fetches only on `doc_changed` for its own doc when `updated_at` differs (a null always does), which is how a delete or a revoked share surfaces as a 404; it ignores `doc_list_changed`, which can be install-wide traffic. Limits (account deletion notifies no one; the everyone broadcast ignores the recipients' gates): [Quest Docs Architecture -- Known Limitations](../architecture/quest-docs.md#known-limitations).

## Agent Tools

Models read and write docs only through `list_docs`, `search_docs`, `read_doc`, `create_doc`, `edit_doc`, `append_to_doc`, `add_doc_image` (`TOOL_CALL_REGISTRY` in `chat/llm/tool_schemas.py`) and the `write_doc` action request. Sandbox scripts get the three reads over the tool-call bridge. None of them can reach the routes above. See [Quest Docs Architecture -- Model-Facing Tools](../architecture/quest-docs.md#model-facing-tools).
